# Development Log — 2026-08-02

### 2026-08-02 (Sidebar 菜单渲染性能：content-visibility 优化屏外节点)

跨项目（nop-app-erp）菜单树较大时，侧边栏一次性全量递归渲染整棵 `MenuItem` 树（含所有折叠分组的子树），DOM 节点数千导致渲染/交互卡顿。

- **根因**：`packages/core/src/components/Sidebar.tsx` 的 `SidebarItem` 折叠态仅靠 `grid-rows-[0fr]` + `overflow-hidden` 把子菜单**视觉高度压 0**，DOM 仍全量挂载；`expanded` 只切 CSS grid 行高，不控制是否挂载。
- **方案 2 实施**（保留展开/折叠动画、改动最小）：给 `SidebarItem` 根 div 加 `contentVisibility: 'auto'` + `containIntrinsicSize: 'auto 2.5rem'`，让浏览器跳过侧边栏滚动区屏外菜单项（含其整棵子树）的 layout/paint。
  - 代码：`packages/core/src/components/Sidebar.tsx:152`
- **能力边界（已告知）**：`content-visibility: auto` 只跳过"与视口不相交"的内容；视口内折叠子菜单位置仍在侧边栏可见区，**不会被跳过**，其 DOM 全量渲染 + React 组件实例化开销不变。即本方案主要改善**滚动/交互**卡顿，对**首屏挂载慢**帮助有限。
- **后备方案（如首屏仍慢）**：升级为方案 1——条件渲染，折叠子菜单 `{expanded && children.map(...)}`，连 DOM/组件都不挂载；代价是丢失高度过渡动画（可淡入补偿）。
- 验证：`pnpm --filter @nop-chaos/core typecheck` ✅、`lint` ✅。待用户实测确认效果。
