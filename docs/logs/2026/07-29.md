# Development Log — 2026-07-29

### 2026-07-29 (afternoon)

- **Flux RPC 参数变换修复**：发现 flux CRUD 生成裸 `/r/OperationName?page=1&perPage=10` URL，不经过 `@query:` 前缀路径，导致 `nopRpcResolver.ts` 的参数变换不生效，后端收到 `page`/`perPage` 参数报 500
- **根因**：`resolveNopRpcUrl` 只处理 `@query:`/`@mutation:` 前缀 URL，不处理 `/r/` 直发 URL。flux 运行时通过 `buildUrlWithParams` 将 `__autoPagination` 作为 URL query 参数添加到 `/r/OperationName` 后面
- **设计文档**：`docs/design/flux-rpc-parameter-transformation.md` 完整记录了参数变换设计
- **重写 `nopRpcResolver.ts`**：遵循原版 `graphqlArgs.ts` 的 `operationRegistry` + `argBuilder` 设计模式，本地实现 builder 函数链：
  - `@query:`/`@mutation:` 走 `operationRegistry` + `buildRpcParams` 完整变换
  - `/r/` 直发路径走 `removeSpecialKeys`（递归过滤 `__`/`@`/`v_` 前缀的运行时参数）
  - 所有 builder（`argQuery`/`argDataMap`/`argString`/等）同原版 AMIS 逻辑
  - `removeSpecialKeys` 在入口统一调用，不在每个 builder 中重复
  - HTTP method 尊重调用方指定的 method，不强制 POST
- **单元测试**：`nopRpcResolver.test.ts` 28/28 通过，涵盖：
  - `@query:` findPage 的 page/perPage → offset/limit 变换
  - `filter_XX` → TreeBean 格式转换（`toFilter`）
  - `orderField`/`orderDir` → `orderBy` 转换
  - `@mutation:` save/update/delete 的 `{data: {...}}` 包装
  - `/r/` URL 的 `__` 前缀递归过滤
  - selection 路径提取和 URL 编码
  - `findList`/`findFirst` 等所有注册操作的参数构建
- **待验证**：重新跑 E2E 测试确认 resource 500 错误是否修复
