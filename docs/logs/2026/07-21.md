- **诊断并修复 nop-entropy-e2e 浏览器测试** — 通过 e2e-shared 诊断工具系统性定位并修复了导致 nop-entropy-e2e 浏览器测试全部失败的多个根因（本项目源码层面）：
  - **Navigation.ts 签名不兼容**：sync 覆盖后 `login(page, { username, password })` 调用不兼容（旧版只接受 `baseUrl?: string`）。升级为 `LoginOptions | string` 联合类型，支持 `username/password/baseUrl` + `E2E_BASE_URL/E2E_USER/E2E_PASSWORD` env var + `E2E_AUTH_MODE=rpc` 快速登录路径
  - **IPv4/IPv6 绑定问题**：macOS 上 Vite dev server 只绑定 `[::1]:4173`（IPv6），但 Navigation.ts 默认 `http://127.0.0.1:4173`（IPv4）→ `ERR_CONNECTION_REFUSED`。改为 `http://localhost:4173`
  - **`waitForFunction` 参数错误**：`page.waitForFunction(fn, { timeout })` 第二个参数是 arg 不是 options → timeout 没生效。改为 `page.waitForFunction(fn, undefined, { timeout })`
  - **登录后菜单未加载导致路由失败**：登录成功后直接导航到 `#/NopAuthUser-main` 时，菜单还没加载、路由没注册 → 重定向到首页。新增 `waitForMenuLoaded()` 等待侧边栏菜单项出现
  - **`waitForAuthenticated` 新增**：替代不可靠的 `waitForLoadState('networkidle')`（Vite HMR 干扰），直接观察 `sessionStorage['auth:v2']` 的 `isAuthenticated` 状态
  - **`CrudListPage.waitForList` 超时增加**：Vite dev 模式下 AMIS 模块逐个加载比预构建慢，从默认 10s（actionTimeout）增加到 30s
  - **`login`/`mockLogin` 命名冲突解决**：index.ts 之前导出 MockAuthAdapter 的 `login` 覆盖了 Navigation 的 `login`。改为 Navigation 的 `login` 为主导出，MockAuthAdapter 的改名为 `mockLogin`。本项目 22 个 spec 文件批量更新为 `import { mockLogin as login }`
  - **nop-code-e2e PO 文件修复**：`type-hierarchy.po.ts` 和 `symbol-search.po.ts` 使用旧的 BasePage API（`private engine` + `super(page)` + 无效的 `override`），改为正确的 `super(page, engine)` + `open()` 方法名（避免与 `BasePage.goto(hashRoute)` 签名冲突）
  - **验证结果**：nop-entropy-e2e 4 包 typecheck 全部通过；本项目 typecheck 28/28、test 28/28（898 tests 全绿）。实际跑 nop-auth-e2e 测试：RPC 测试（15个）全部通过；浏览器导航测试（角色管理页面 2.2s、用户管理页面 4.9s）成功渲染 AMIS CRUD 表格；但部分浏览器交互测试仍因 nop-entropy 后端 Quarkus dev 模式不稳定（ClassNotFoundException + live reload 崩溃）而间歇性失败
