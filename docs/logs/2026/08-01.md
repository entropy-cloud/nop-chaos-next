### 2026-08-01 (deep dive: submitAction lazy 执行验证)

按"在 nop-chaos-flux 增加测试验证 + 查看源码"的指示完成 flux 侧验证：

- **源码分析结论**：submitAction 的设计就是**延迟执行（lazy）**：
  - 编译层：`action-compiler.ts` 用 `compileValue(action.args)` → `${field}` 模板编译为 **dynamic**（`CompiledRuntimeValue`），`symbolTable` 只含内建（$Math/$JSON/$Date），不含表单字段 → 不预烘焙
  - dispatch 层：`node-renderer-resolved.tsx` 事件处理器在**事件触发时**才 `helpers.dispatch`；form.tsx 用 `scope: lifecycleScope`（= ownedForm.scope，store=form values）
  - 求值层：`evaluateCompiledInActionContext` 在 dispatch 时对 `getEvaluationScope(ctx)` 求值 → 读 form store 当前值
- **新增测试（全部通过）**：
  - `flux-renderers-form/src/__tests__/submit-action-lazy-execution.test.tsx`：loadAction→编辑→提交，payload 必须携带编辑后的值（lazy 契约）
  - `tests/e2e/component-lab/dialog-real-schema.spec.ts`：**真实 nop-entropy 编辑 schema 原样加载**（tabs + dict combobox + tree-select + picker + upload + 18 字段 submitAction + dialog actions）→ 真实浏览器提交编辑值 ✅
  - `dialog-edit-submit.spec.ts` 升级为 tabs + combobox + 多字段
- **真实 schema 在 flux playground 真实浏览器通过**——flux 运行时对真实 schema 完全正确
- **剩余结论**：flux 运行时、真实 schema、host mock 内联 JSON 全部正确。唯一失败的组合是 **host dev 模式 + 真实后端**（nopRpcResolver + 真实响应处理），无法在 flux 侧复现。这是 host 集成层的剩余疑点。
