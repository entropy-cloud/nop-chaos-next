# Development Log — 2026-08-29

### 2026-08-29 (完全独立 extension-demo + verify-imports + 双 dev 模式)

- **新增 `examples/extension-demo-external/`**：完全独立的项目，不使用 workspace:* 依赖，模拟"外部开发者拿到 sdks/ 后的真实环境"。
  - `package.json`：所有 SDK 依赖用 `file:./sdks/*.tgz`（相对项目内 `sdks/` 目录）
  - **`pnpm setup`**：把 monorepo 的 `dist/sdks/` 内容拷到本项目的 `sdks/`
  - **`preinstall` hook**（`scripts/check-sdks.mjs`）：校验 sdks/ 完整，缺失时提示运行 `pnpm pack:sdk`
  - **`pnpm verify:imports`**（`scripts/verify-imports.mjs`）：动态加载每个 SDK 包，验证关键导出存在
    - 6 个核心包：运行时加载，校验命名导出
    - 5 个 DOM-only 包（flux/amis）：只校验 tarball 已安装
  - **`pnpm dev`**（真实后端）：`scripts/check-host-dist.mjs` 校验后跑 vite（要求 Java 后端运行在 :8080）
  - **`pnpm dev:mock`**（前端 mock）：`scripts/check-host-dist-mock.mjs` 校验后跑 vite（要求宿主用 `--mode devtools-e2e` 构建，含 mock API）
  - **`pnpm dev:standalone`**：仅扩展 UI，不连宿主

- **`tools/extension-host-shell-plugin.mjs`**：增加 `HOST_DIST_MOCK` 环境变量解析（mock 模式优先级高于 HOST_DIST）。

- **`hostShellPlugin` 修复**（`examples/extension-demo` 升级时发现的两个 bug）：
  - **MIME 类型丢失**：非 HTML 静态文件 pipe 时未设 Content-Type，浏览器拒加载。修复：`getMimeType()` 函数 + `MIME_TYPES` 表。
  - **Vite `/@id/...` URL 重写错误**：`resolveId({external: true})` 让 Vite 把共享模块重写成 `/@id/<name>`，但这些 URL 在宿主模块图里不存在（404）。修复：改用 `transform` 钩子，把输出里的 `/@id/<shared>` 重写回裸名（`react` 等），让浏览器用宿主 import map 解析到 facade。

### 2026-08-29 (单命令调试 + extension-demo 升级 + 文档澄清)

- **单命令调试（核心改进）**：扩展项目的 `pnpm dev` 现在自动加载宿主页面并注入自身，无需 `serve` + `dev-in-host` + `build` 三套进程。
  - **`tools/extension-host-shell-plugin.mjs`**（新）：Vite 插件，把宿主 dist（`index.html`/`assets/`/`nop-shared/`）服务出来，注入 `<script>__NOP_EXTENSIONS__=...</script>`，扩展源由 Vite 提供（带 HMR）。
  - **`HOST_DIST` 解析优先级**：env var → `../../apps/main/dist`（同级放置 nop-chaos-next 仓库）→ 降级 standalone（友好提示）。
  - **`setup-extension.mjs init`** 生成 `vite.config.ts`（带 plugin）+ `vite.standalone.config.ts`（降级）+ `extension-host-shell-plugin.mjs`（从 sdks 拷贝）。
  - **`pack-sdks.mjs`** 把插件拷贝到 `dist/sdks/`。
  - **API proxy（dev 模式）**：宿主生产 dist 不含 proxy，`hostShellPlugin` 复刻宿主原 vite dev proxy：把 `/r/*`、`/graphql`、`/p/*`、`/f/*`、`/q/*` 转发到 `BACKEND_ORIGIN`（默认 `http://localhost:8080`，可覆盖）。`HOST_DIST_MOCK` 模式下跳过 proxy（mock 宿主自带 mock API）。

### 2026-08-29 (扩展项目初始化工具：setup-extension.mjs)

- **新增 `tools/setup-extension.mjs`**：随 SDK 分发的项目初始化脚本，自动从 `version-manifest.json` 读取宿主实际依赖版本，无需手动指定。
  - `init --id <id> --name <name> [--target <dir>]`：新建扩展项目（目标目录必须无 package.json），生成 package.json / tsconfig.json / vite.config.ts / src/index.ts / src/standalone/
  - `add [--target <dir>]`：向已有项目添加 SDK 依赖（目标目录必须有 package.json）
  - 严格校验：init 时 package.json 已存在则报错，add 时无 package.json 则报错
  - 自动安装 6 个 SDK + 5 个 vendored 渲染引擎（flux/amis）
  - React/ReactDOM 版本从 `apps/main/package.json` 读取，确保与宿主一致
  - 自动添加 `@types/react`、`@types/react-dom`、vite、typescript 等 devDependencies

- **修改 `tools/pack-sdks.mjs`**：
  - 新增 `writeVersionManifest()`：生成 `dist/sdks/version-manifest.json`，包含 hostApiVersion、dependencies（React 等实际版本）、sdkPackages、vendoredPackages
  - 新增 `readHostApiVersion()`：从 `packages/shared/src/version.ts` 读取 HOST_API_VERSION
  - 自动拷贝 `setup-extension.mjs` 到 `dist/sdks/`

- **产物（dist/sdks/）**：
  - 11 个 tarball（6 SDK + 5 vendored 引擎）
  - `version-manifest.json`（依赖版本清单）
  - `setup-extension.mjs`（项目初始化脚本）

- **验证**：
  - init 模式：创建临时项目 → pnpm install → tsc --noEmit 零错误 → nop-extension-dev build 成功
  - add 模式：向已有项目添加依赖 → 正确更新 package.json
  - 错误处理：init 时 package.json 已存在 → 报错退出；add 时无 package.json → 报错退出

- **文档**：`docs/design/extension-development-guide.md` §3.1/§3.2/§9 更新
