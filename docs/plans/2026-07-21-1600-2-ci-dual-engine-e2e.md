# nop-chaos-next CI 双引擎 E2E 集成

> Plan Status: completed
> Last Reviewed: 2026-07-21

> Mission: e2e-upgrade
> Work Item: Phase 4.4 + 5.1 — CI 双引擎矩阵 + nop-chaos-next CI 接入 e2e

## Purpose

为 nop-chaos-next 创建 GitHub Actions CI 工作流，在每次推送和 PR 时自动运行 E2E 测试（`E2E_ENGINE=amis` 和 `E2E_ENGINE=flux` 双引擎），完成后 roadmap Phase 4.4（CI 双引擎矩阵）和 Phase 5.1（nop-chaos-next CI 接入 e2e）同时达成。

## Current Baseline

- nop-chaos-next 使用 Turborepo 构建系统，`turbo.json` 定义了构建缓存与依赖拓扑
- `pnpm build`（turbo run build）可执行全量构建
- `pnpm test:e2e` 使用 Playwright，默认 `E2E_ENGINE=amis` 模式
- `E2E_ENGINE=flux pnpm test:e2e` 可运行 Flux 引擎测试（14 个 flux-crud tests，Phase 4.2）
- Phase 4.3（Flux dashboard + report 测试）完成后，`E2E_ENGINE=flux` 将获得额外测试覆盖
- Playwright config 已支持 `CI` env var（`forbidOnly: true`, `retries: 2`）
- 当前无 `.github/` 目录 — 无 GitHub Actions 工作流
- `playwright.config.ts` 配置了 HTML reporter、trace/screenshot/video 产物
- Turborepo 远程缓存未配置；CI 上 turbo 将全量构建（无缓存命中）
- nop-chaos-next 使用 mock 模式运行 e2e（无需外部后端），CI 可纯前端完成
- `playwright.config.ts` 的 webServer 命令使用 `vite build` + `vite preview`（非 prototype 模式下）
- Phase 5.4（E2E 文档化）已完成，`docs/testing/01-e2e-developer-guide.md` 包含 CI 运行说明占位

## Goals

- 创建 `.github/workflows/e2e.yml` GitHub Actions 工作流：
  - 在 push 到 main 和 PR 时触发
  - Node.js 环境 + pnpm 安装
  - Turbo build（`pnpm build`）
  - Playwright 浏览器安装
  - 运行 `E2E_ENGINE=amis pnpm test:e2e`（AMIS 引擎）
  - 运行 `E2E_ENGINE=flux pnpm test:e2e`（Flux 引擎，Phase 4.3 完成后）
  - 失败时上传 Playwright artifacts（HTML report、trace、screenshot、video）
  - 可单独选择引擎模式运行
- 合并到 main 后，PR 状态检查中显示 e2e 结果
- 验证 CI 工作流在 dry-run 级别可解析（语法 + 依赖正确）
- 更新 `docs/backlog/e2e-upgrade-roadmap.md` 标记 4.4 和 5.1 为完成

## Non-Goals

- 不配置 nop-entropy CI（Phase 5.2）
- 不配置 nop-app-erp CI（Phase 5.3）
- 不添加 Turborepo 远程缓存配置（独立优化项）
- 不修改 e2e 测试代码或 Playwright 配置
- 不在 CI 上运行 `pnpm lint` 或 `pnpm test`（已有其他流程覆盖，turbo 的 dependency 会自然触发）

## Scope

### In Scope

- 创建 `.github/workflows/e2e.yml`
- 使用 `actions/setup-node` + `pnpm/action-setup` 安装依赖
- Turbo build 作为 e2e 前置步骤
- Playwright 浏览器安装（`npx playwright install chromium`）
- 串行/并行运行 AMIS 和 Flux 双引擎 e2e 测试（确保不互相干扰）
- Artifact 上传策略（HTML report、trace、screenshot、video 仅在失败时保留）
- 工作流触发条件：push to main, pull_request to main
- CI 环境中 `CI=true` 已由 Playwright config 识别（forbidOnly, retries）
- 支持手动触发（`workflow_dispatch`）选择引擎类型

### Out Of Scope

- nop-entropy-e2e CI（Phase 5.2）
- nop-app-erp CI 加固（Phase 5.3）
- Turborepo 远程缓存配置
- nop-chaos-next 之外的 CI/CD 基础设施
- 部署或预览环境
